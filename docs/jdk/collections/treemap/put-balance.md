# TreeMap：插入平衡、旋转与删除修复

`put` 先按普通二叉搜索树接入节点，`fixAfterInsertion` 再修复颜色约束。阅读这一段源码时，不要把“查找位置”和“恢复平衡”混成一个过程：前者只比较 key，后者只关心节点关系与颜色。

## 为什么新节点先标红

新节点接入时两个孩子都是逻辑上的黑色 `null` 叶子。若直接把新节点标黑，从新节点经过的路径会凭空多一个黑节点，立刻破坏黑高；标红不会改变任何路径的黑节点数量，可能造成的唯一问题是“父红、子红”。

因此插入修复循环只在下面条件同时成立时继续：

```text
x 不是根节点
x 的父节点是红色
```

父节点为黑色时，新增红节点没有破坏任何不变量，可以直接结束。无论循环走过哪些分支，最后都会把根节点设为黑色。

### 最后一次插入的变量快照

8 按二叉搜索树规则接入、`fixAfterInsertion` 刚开始时，相关局部结构为：

```text
        2(B)
           \
            4(R)
               \
                6(B)
               /   \
            5(R)   7(R)
                      \
                       8(R)  ← x
```

第一轮循环：

| 变量 | 值 |
| --- | --- |
| `x` | 8 |
| `parentOf(x)` | 7，红色 |
| `parentOf(parentOf(x))` | 6，黑色 |
| `y`（叔父） | 5，红色 |
| 动作 | 5、7 变黑，6 变红，`x = 6` |

第二轮循环：

| 变量 | 值 |
| --- | --- |
| `x` | 6，红色 |
| `parentOf(x)` | 4，红色 |
| 祖父 | 2，黑色 |
| 叔父 | 1，黑色 |
| 形状 | x 是父的右孩子，父也是祖父的右孩子 |
| 动作 | 4 变黑，2 变红，`rotateLeft(2)` |

最终根节点变成 4，中序顺序仍为 `1, 2, 3, 4, 5, 6, 7, 8`。旋转只改变链接，不改变比较顺序。

## fixAfterInsertion 的分支表

源码先判断 parent 位于 grandparent 的左侧还是右侧。左右两半完全镜像，先掌握 parent 在左侧的三种情况：

| parent 在祖父左侧时 | 判断 | 处理 |
| --- | --- | --- |
| 叔父红 | `colorOf(uncle) == RED` | parent、uncle 变黑，grandparent 变红，`x` 上移到 grandparent |
| 左右三角 | x 是 parent 的右孩子，叔父黑 | 先令 `x = parent`，对旧 parent 左旋，把三角转成左左直线 |
| 左左直线 | x 是 parent 的左孩子，叔父黑 | parent 变黑、grandparent 变红，再对 grandparent 右旋 |

parent 在祖父右侧时取镜像动作：

| 形状 | 预处理 | 最终动作 |
| --- | --- | --- |
| 右左三角 | 先对 parent 右旋 | parent/祖父重着色，再对祖父左旋 |
| 右右直线 | 无 | parent/祖父重着色，再对祖父左旋 |
| 叔父红 | 不看 x 位于哪一侧 | 两个孩子变黑、祖父变红，焦点上移 |

口诀只能帮助定位，不能代替变量跟踪。真正可靠的断点顺序是每轮都记录 `x`、parent、grandparent、uncle，以及 parent/x 分别位于哪一侧。

## 左旋到底修改了哪些链接

以 `rotateLeft(p)` 为例，必须保证 `p.right` 是要提升的节点 `r`。概念变化是：

```text
旋转前                 旋转后
    p                      r
   / \                    / \
  a   r        →         p   c
     / \                / \
    b   c              a   b
```

实现需要按安全顺序同步六类关系：

1. `r.left` 子树 b 改为 `p.right`。
2. b 非空时，把 b 的 parent 改回 p。
3. r 接管 p 原来的 parent。
4. p 原来是根时更新 root；否则修改祖父指向 p 的那条边。
5. p 成为 r 的左孩子。
6. p 的 parent 改为 r。

右旋完全镜像。最容易漏看的不是左右孩子，而是 parent 与 root：如果只画向下的边，很难发现源码为什么需要这么多赋值。

::: tip 旋转不会重新比较 key
旋转建立在原有二叉搜索树关系上。a 中的键小于 p，b 的键介于 p 与 r 之间，c 中的键大于 r，所以换链接后中序顺序保持不变。
:::

## 重着色为什么可能向上传播

叔父为红时，parent 与 uncle 同时变黑可以消除 x 与 parent 的连续红；grandparent 变红则抵消左右路径新增的黑节点。局部黑高恢复了，但 grandparent 可能与它的父亲连续为红，因此源码把 `x` 提升到 grandparent 再进入下一轮。

旋转分支会在当前层终止：直线或三角被整理后，新局部根是黑色，两个子分支的黑高相同，也没有连续红需要继续上推。

## 删除先把问题压缩到至多一个孩子

`remove` 先通过 `getEntry` 定位节点，再进入 `deleteEntry`。删除节点有两个孩子时，JDK 8 不直接搬动整棵后继子树，而是：

1. 找到待删节点的中序后继 `s`，也就是右子树中的最小节点。
2. 把 `s.key` 与 `s.value` 复制到原待删节点。
3. 把变量 `p` 改为后继 `s`，真正从树上删除 s。

后继不可能有左孩子，因此转换后实际被摘除的节点至多有一个非空孩子。注意这是内部节点内容复制：公开行为是目标 key 消失，不能依赖内部 Entry 对象身份保持不变。

### deleteEntry 的三个结构分支

| 被实际摘除的节点 | 处理方式 | 是否调用删除修复 |
| --- | --- | --- |
| 有一个非空孩子 `replacement` | replacement 接管 p 的父链接，再断开 p | p 为黑色时，从 replacement 开始 |
| p 是整棵树唯一节点 | `root = null` | 不需要 |
| p 是叶子 | p 暂时充当“幻影替代节点”，修复结束后再断开 | p 为黑色时调用 |

黑色叶子被删除时，源码不能把 `x` 直接设为 `null`，否则无法知道它原来位于父节点哪一侧。JDK 8 让仍带 parent 的 p 暂时进入 `fixAfterDeletion`，完成修复后才把它从父节点断开。

## fixAfterDeletion 的四类情况

删除黑节点可能让 x 所在路径少一个黑节点。以 x 是 parent 左孩子为例，`sib` 是右兄弟；另一半代码完全镜像：

| 情况 | 颜色条件 | 处理目的 |
| --- | --- | --- |
| 兄弟红 | sib 红，parent 必为黑 | sib 变黑、parent 变红，对 parent 左旋，转换成黑兄弟情形 |
| 兄弟及其孩子全黑 | sib、sib.left、sib.right 都黑 | sib 变红，把缺失的黑高问题上推到 parent |
| 远侄黑、近侄红 | sib 黑，sib.right 黑，sib.left 红 | 近侄变黑、sib 变红，对 sib 右旋，转换成远侄红 |
| 远侄红 | sib 黑，sib.right 红 | sib 继承 parent 颜色，parent 与远侄变黑，对 parent 左旋并结束 |

这里的“近”和“远”以 x 为参照：x 在左侧时，兄弟的左孩子是近侄、右孩子是远侄。x 在右侧时方向反过来。

动画中的 `5*`、`1*`、`4*` 表示源码尚未从父节点断开的黑色叶子。它不是新建的哨兵对象；JDK 8 复用待摘除 Entry 充当 x，修复结束后才把链接清空。三组输入覆盖的是源码分支，不应把最终某个节点的精确颜色当成跨版本公开契约。

`colorOf(null)` 返回黑色，`leftOf(null)` 和 `rightOf(null)` 返回 `null`，让同一套条件可以覆盖缺失节点。循环退出后会把 x 设为黑色，补齐最后的颜色边界。

## size 与 modCount 的时机

- 新 key：完成接入和插入修复后，`size` 与 `modCount` 各增加一次。
- 覆盖 key：只替换 value，二者都不变。
- 删除命中：`deleteEntry` 一开始就让 `size--`、`modCount++`，随后再处理链接和颜色。
- 删除未命中：直接返回，二者不变。

颜色变化和旋转不是额外的结构性操作计数。一次公开 `put/remove` 最多让 `modCount` 改变一次。

## 性能与版本边界

一次插入最多沿树高向上重着色，旋转次数是常数级；删除修复也最多沿树高上移。因此定位与修复合计仍为 O(log n)。

本文的 `fixAfterInsertion`、`deleteEntry`、`fixAfterDeletion`、`rotateLeft` 和 `rotateRight` 名称对应 OpenJDK 8u。较新 JDK 可以重排私有实现；稳定契约是有序 Map 的公开行为与对数级基本操作，不是某次输入后的精确颜色图。
