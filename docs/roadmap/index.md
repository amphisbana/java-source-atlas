# 项目路线图

Java Source Atlas 的目标是把“想读源码”变成一条可以定位、运行和验证的学习路径。路线图按读者价值排序，具体排期会根据 Issue、Discussion 和维护成本调整。

## 当前版本：可验证的源码阅读闭环

- 统一 JDK、Spring Framework 与 Spring Boot 的专题索引。
- 为关键入口提供调用链、推荐断点、Lab、测试和版本基线。
- IDEA 插件支持类/方法上下文匹配、源码定位、断点添加、IDE 内阅读和学习进度。
- IDEA 插件首次打开可检查教程站、项目结构、源码与 Lab 环境，并能自动添加断点后 Debug 精确 JUnit 场景。
- 文档站提供版本对比、交互动画、学习路线和跨专题深挖。
- 29 个专题已补齐 87 条结构化证据，推荐断点可绑定并直接 Debug 对应 JUnit 场景。

## 下一阶段

### P0：让每个专题都能复现

- [x] 为已有专题补齐主线、失败或边界条件和最小可运行测试。
- 继续覆盖 JDK 8、17、21 的实现差异，并标注哪些结论属于公开契约。
- [x] 把断点与 JUnit 证据场景的关系写进专题索引，减少“断点存在但不知道如何触发”的情况。

### P1：提高阅读效率

- [x] 插件增加阅读会话、方法级恢复、调用链前后导航和编辑器上下文动作。
- [x] 插件增加推荐断点观察清单、Watches 便捷操作和插件断点生命周期管理。
- [x] 插件命中 Atlas 断点后展示当前证据、预期状态和下一推荐断点。
- 插件继续完善按版本切换教程和保存个人阅读笔记。
- 文档站支持专题收藏、最近阅读和学习进度跨设备导出。
- 为高复杂度状态机补充可暂停、可回放的动画与事件时间线。

### P2：扩大社区共建

- 建立专题提案、Lab 分享和版本差异讨论模板。
- [x] 为新贡献者提供从源码入口到测试、证据绑定和 PR 校验的端到端示例。
- [x] 接入 JetBrains Marketplace 发布准备，并为文档交互和 IDEA 兼容性增加自动化门禁。
- 对高频专题维护变更日志和贡献者名单，保留每次结论的证据来源。

## 不在近期范围内

- 不把第三方源码整段复制到仓库；优先链接固定版本上游源码并解释关键片段。
- 不为了覆盖数量而生成没有 Lab、断点或测试的“目录式文章”。
- 不承诺所有 JDK、Spring 版本都拥有同等深度；先维护 8 / 17 / 21 和 Spring 5 / Boot 2.7 基线。

## 如何影响路线图

请先搜索现有专题和 Issue，再通过[专题建议](https://github.com/amphisbana/java-source-atlas/issues/new?template=topic_request.yml)、[Discussion](https://github.com/amphisbana/java-source-atlas/discussions) 或[在线反馈](/guide/feedback)提交问题。一个好的提案应包含目标版本、真实问题、源码入口和可验证的最小案例。
